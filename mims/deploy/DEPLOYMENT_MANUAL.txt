PART A  —  OVERVIEW & REQUIREMENTS
================================================================================

WHAT THIS SYSTEM IS
-------------------
  M-IMS is a Hospital Medicine Inventory Management System.
  It includes:
    - Frontend web application  (runs on port 3000)
    - Backend REST API          (runs on port 3001)
    - PostgreSQL database       (runs internally inside Docker)
    - Redis cache               (runs internally inside Docker)
    - Nginx reverse proxy       (runs on port 80 — main access point)

HOW USERS ACCESS IT
-------------------
  Users open a web browser on any computer on the hospital's local network
  and go to:    http://<SERVER-IP-ADDRESS>/
  Example:      http://192.168.1.100/

  There is NO internet required. Everything runs locally.

WHAT RUNS ON THE CLIENT SERVER
-------------------------------
  Everything runs inside Docker containers.
  The client server needs ONLY:
    - Docker
    - Docker Compose
  Nothing else is installed directly on the machine.

MINIMUM SERVER REQUIREMENTS (CLIENT MACHINE)
---------------------------------------------
  Operating System  : Ubuntu 22.04 LTS  (recommended)
                      OR  Ubuntu 20.04 LTS
                      OR  Debian 11/12
                      OR  CentOS/RHEL 8+
                      OR  Windows Server 2019+ with WSL2 + Docker Desktop
  CPU               : 4 cores minimum (8 cores recommended)
  RAM               : 8 GB minimum (16 GB recommended)
  Disk Space        : 50 GB free minimum (100 GB recommended for database growth)
  Network           : Connected to hospital LAN
  Internet Access   : Only needed ONCE during initial Docker installation
                      Not needed for day-to-day operation

PART C  —  WHAT TO COLLECT FROM THE CLIENT SERVER
================================================================================

  These steps are performed ON THE CLIENT SERVER.
  You need physical or remote access to the client server to do this.

  GOAL: Collect the machine's unique fingerprint so we can generate
  a license key that is locked to THAT specific machine.

------------------------------------------------------------------------
STEP C-1: CONNECT TO THE CLIENT SERVER
------------------------------------------------------------------------

  Option A — Physical access:
    Sit at the server machine, open a terminal.

  Option B — SSH remote access:
    ssh username@<SERVER-IP-ADDRESS>

  Once connected, you should see a command prompt.

------------------------------------------------------------------------
STEP C-2: CHECK THE SERVER'S MACHINE ID
------------------------------------------------------------------------

  Run this command:

    cat /etc/machine-id

  Expected output — a 32-character hex string. Example:
    d8f3a1b2c4e5f6a7b8c9d0e1f2a3b4c5

  WRITE THIS DOWN. You will need it to generate the license.

  If that file doesn't exist, try:
    cat /var/lib/dbus/machine-id

  On Windows Server:
    wmic csproduct get uuid

------------------------------------------------------------------------
STEP C-3: CHECK THE SERVER'S MAC ADDRESSES
------------------------------------------------------------------------

  Run this command on Linux:

    ip link show | grep -E "^[0-9]|link/ether" | grep -v "00:00:00:00:00:00"

  This will show output like:
    2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
        link/ether aa:bb:cc:dd:ee:ff brd ff:ff:ff:ff:ff:ff
    3: eth1: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
        link/ether 11:22:33:44:55:66 brd ff:ff:ff:ff:ff:ff

  WRITE DOWN ALL MAC ADDRESSES shown.
  Use ONLY the physical/real network cards (not virtual, not loopback).

  On macOS:
    ifconfig | grep ether

  On Windows Server:
    ipconfig /all | findstr "Physical Address"

------------------------------------------------------------------------
STEP C-4: CHECK THE SERVER'S IP ADDRESS
------------------------------------------------------------------------

  Run:
    ip addr show | grep "inet " | grep -v 127.0.0.1

  Example output:
    inet 192.168.1.100/24 brd 192.168.1.255 scope global eth0

  WRITE DOWN: 192.168.1.100  (this is the server IP address)
  This is what hospital users will type in their browsers.

------------------------------------------------------------------------
STEP C-5: RECORD ALL INFORMATION ON PAPER
------------------------------------------------------------------------

  Fill in this form on paper or a text file. Keep it secure.

  ┌─────────────────────────────────────────────────────────────┐
  │  M-IMS CLIENT SERVER FINGERPRINT RECORD                     │
  ├─────────────────────────────────────────────────────────────┤
  │  Hospital Name    : ____________________________________     │
  │  Contact Person   : ____________________________________     │
  │  Server Hostname  : ____________________________________     │
  │  Server IP Address: ____________________________________     │
  │  Operating System : ____________________________________     │
  │  Machine ID       : ____________________________________     │
  │  MAC Address 1    : ____________________________________     │
  │  MAC Address 2    : ____________________________________(opt)│
  │  Date Collected   : ____________________________________     │
  └─────────────────────────────────────────────────────────────┘

------------------------------------------------------------------------
STEP C-6: INSTALL DOCKER ON THE CLIENT SERVER (if not already installed)
------------------------------------------------------------------------

  Check if Docker is installed:
    docker --version

  If NOT installed, run these commands (Ubuntu/Debian):

    # Update package list
    sudo apt-get update

    # Install prerequisites
    sudo apt-get install -y ca-certificates curl gnupg lsb-release

    # Add Docker's official GPG key
    sudo install -m 0755 -d /etc/apt/keyrings
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
      sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
    sudo chmod a+r /etc/apt/keyrings/docker.gpg

    # Set up the repository
    echo \
      "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
      https://download.docker.com/linux/ubuntu \
      $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
      sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

    # Install Docker
    sudo apt-get update
    sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

    # Start Docker and enable on boot
    sudo systemctl start docker
    sudo systemctl enable docker

    # Allow current user to run docker without sudo
    sudo usermod -aG docker $USER
    newgrp docker

    # Verify installation
    docker --version
    docker compose version

  For CentOS/RHEL:
    sudo yum install -y yum-utils
    sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
    sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
    sudo systemctl start docker
    sudo systemctl enable docker
    sudo usermod -aG docker $USER

  NOTE: If the server has NO internet access, you must install Docker
  from the USB drive using offline packages. Ask your IT team for the
  Docker offline .deb/.rpm packages for your OS version.

------------------------------------------------------------------------
STEP C-7: CREATE THE APPLICATION DIRECTORY ON THE CLIENT SERVER
------------------------------------------------------------------------

    sudo mkdir -p /opt/mims
    sudo chown $USER:$USER /opt/mims
    cd /opt/mims

  This is where the application will live permanently.

PART D  —  GENERATING THE LICENSE KEY (Vendor Step — Back on Dev Machine)
================================================================================

  Go back to YOUR development machine now.
  You need the Machine ID and MAC address(es) you wrote down in PART C.

------------------------------------------------------------------------
STEP D-1: GENERATE THE LICENSE KEY
------------------------------------------------------------------------

  Run this command on your dev machine, replacing the values with what
  you collected from the client server:

    cd /Users/mapmac/Hospital-Medicine-IMS/mims/backend

    npx ts-node scripts/generate-license.ts \
      --client-name="HOSPITAL_NAME_HERE" \
      --licensed-to="CONTACT_PERSON_NAME" \
      --machine-id="PASTE_MACHINE_ID_HERE" \
      --mac="PASTE_MAC_ADDRESS_1_HERE" \
      --mac="PASTE_MAC_ADDRESS_2_HERE" \
      --expires="2027-12-31"

  REAL EXAMPLE:
    npx ts-node scripts/generate-license.ts \
      --client-name="Al-Noor General Hospital" \
      --licensed-to="Dr. Ahmed Al-Rashidi" \
      --machine-id="d8f3a1b2c4e5f6a7b8c9d0e1f2a3b4c5" \
      --mac="aa:bb:cc:dd:ee:ff" \
      --mac="11:22:33:44:55:66" \
      --expires="2027-12-31"

  NOTES:
    - --expires is optional. Leave it out for a perpetual license.
    - You can add multiple --mac arguments (one per line).
    - The date must be in YYYY-MM-DD format.

------------------------------------------------------------------------
STEP D-2: CHECK THE OUTPUT
------------------------------------------------------------------------

  After running the command you will see:

    ✅ License generated successfully!
       📄 License file  : /path/to/dist-protected/license.key
       📋 License info  : /path/to/dist-protected/license.info

  Two files are created:
    license.key  — This is the ENCRYPTED license. GIVE THIS TO THE CLIENT.
    license.info — This is your vendor record. KEEP THIS. NEVER SHARE IT.

------------------------------------------------------------------------
STEP D-3: COPY license.key INTO THE OUTPUT FOLDER
------------------------------------------------------------------------

    cp /Users/mapmac/Hospital-Medicine-IMS/mims/backend/dist-protected/license.key \
       /Users/mapmac/Hospital-Medicine-IMS/mims/deploy/output/license.key

------------------------------------------------------------------------
STEP D-4: KEEP license.info IN YOUR VENDOR RECORDS
------------------------------------------------------------------------

  Store license.info in your company records.
  You will need it if the client's hardware changes and they need a
  re-issued license.

  Store in your company folder (NOT on USB that goes to client):
    /Users/mapmac/Hospital-Medicine-IMS/mims/deploy/vendor-records/
      license-HOSPITAL_NAME-YYYY-MM-DD.info

STEP E-5: SET UP LOG DIRECTORY
------------------------------------------------------------------------

    mkdir -p /opt/mims/logs

------------------------------------------------------------------------
STEP E-6: SET UP AUTO-START ON BOOT
------------------------------------------------------------------------

  Create a systemd service so the system starts automatically when the
  server reboots:

    sudo nano /etc/systemd/system/mims.service

  Paste this content:

  ─────────────────────────────────────────────────────────
  [Unit]
  Description=M-IMS Hospital Management System
  Requires=docker.service
  After=docker.service network-online.target
  Wants=network-online.target

  [Service]
  Type=oneshot
  RemainAfterExit=yes
  WorkingDirectory=/opt/mims
  ExecStart=/usr/bin/docker compose up -d
  ExecStop=/usr/bin/docker compose down
  TimeoutStartSec=300
  User=root

  [Install]
  WantedBy=multi-user.target
  ─────────────────────────────────────────────────────────

  Save: Ctrl+O → Enter → Ctrl+X

  Enable the service:
    sudo systemctl daemon-reload
    sudo systemctl enable mims.service

------------------------------------------------------------------------
STEP E-7: CONFIGURE FIREWALL (if ufw is active)
------------------------------------------------------------------------

    sudo ufw status

    sudo ufw allow 80/tcp comment 'M-IMS Web'
    sudo ufw allow 22/tcp comment 'SSH'
    sudo ufw reload

  Do NOT open ports 3000, 3001, 5432, or 6379 — they must stay private.

PART I  —  DAILY OPERATIONS & MAINTENANCE
================================================================================

------------------------------------------------------------------------
CHECKING SYSTEM STATUS (run anytime)
------------------------------------------------------------------------

    cd /opt/mims
    docker compose ps

------------------------------------------------------------------------
VIEWING LOGS
------------------------------------------------------------------------

  All logs:
    docker compose logs

  Backend logs only:
    docker compose logs backend --tail=100

  Follow live logs:
    docker compose logs -f backend

  License audit log (unauthorized attempt tracking):
    docker compose exec backend cat /app/license-audit.log

------------------------------------------------------------------------
RESTARTING THE SYSTEM
------------------------------------------------------------------------

  Restart everything:
    cd /opt/mims
    docker compose restart

  Restart only backend:
    docker compose restart backend

------------------------------------------------------------------------
STOPPING THE SYSTEM
------------------------------------------------------------------------

    cd /opt/mims
    docker compose down

  Note: Database data is preserved in Docker volumes even when stopped.

------------------------------------------------------------------------
DATABASE BACKUP (RUN DAILY)
------------------------------------------------------------------------

  Create a backup script:

    nano /opt/mims/backup.sh

  Paste this:
  ─────────────────────────────────────────────────────────
  #!/bin/bash
  BACKUP_DIR=/opt/mims/backups
  DATE=$(date +%Y-%m-%d_%H-%M)
  mkdir -p $BACKUP_DIR

  docker compose exec -T postgres pg_dump \
    -U $DB_USERNAME $DB_NAME \
    | gzip > $BACKUP_DIR/mims_backup_$DATE.sql.gz

  # Keep only last 30 days of backups
  find $BACKUP_DIR -name "*.sql.gz" -mtime +30 -delete

  echo "Backup completed: mims_backup_$DATE.sql.gz"
  ─────────────────────────────────────────────────────────

  Make it executable and schedule it:

    chmod +x /opt/mims/backup.sh

    # Add to crontab (runs daily at 2:00 AM)
    crontab -e
    # Add this line:
    0 2 * * * /opt/mims/backup.sh >> /opt/mims/logs/backup.log 2>&1

------------------------------------------------------------------------
RESTORING FROM BACKUP
------------------------------------------------------------------------

    # Stop the application
    docker compose down

    # Restart just the database
    docker compose up -d postgres

    # Wait 10 seconds for database to start
    sleep 10

    # Restore
    gunzip < /opt/mims/backups/mims_backup_YYYY-MM-DD_HH-MM.sql.gz | \
      docker compose exec -T postgres psql -U mims_user mims_db

    # Start everything again
    docker compose up -d

------------------------------------------------------------------------
SYSTEM UPDATE PROCEDURE (when new version is available)
------------------------------------------------------------------------

  1. Receive new image tarballs from vendor
  2. Copy them to /opt/mims/
  3. Run:
       cd /opt/mims
       docker load < mims-backend-NEW_VERSION.tar.gz
       docker load < mims-frontend-NEW_VERSION.tar.gz
       # Update APP_VERSION= in .env file
       nano .env    # change APP_VERSION=1.0.0 to the new version
       docker compose up -d --no-build
  4. Verify everything works (PART G checks)

PART J  —  TROUBLESHOOTING
================================================================================

------------------------------------------------------------------------
PROBLEM: License validation failed — MACHINE_MISMATCH
------------------------------------------------------------------------

  Error seen in logs:
    Status: MACHINE_MISMATCH

  CAUSE: The license.key was generated for a different machine.

  SOLUTION:
    1. On the server, run:
         cat /etc/machine-id
         ip link show | grep "link/ether"
    2. Send these values to the vendor.
    3. Vendor generates a new license key with the correct machine info.
    4. Vendor sends back a new license.key file.
    5. Replace the old file:
         cp new-license.key /opt/mims/license.key
         docker compose restart backend

------------------------------------------------------------------------
PROBLEM: License validation failed — NOT_FOUND
------------------------------------------------------------------------

  Error seen in logs:
    Status: NOT_FOUND

  CAUSE: The license.key file is missing from /app/ inside the container.

  SOLUTION:
    1. Verify the file exists on the host:
         ls -la /opt/mims/license.key
    2. Verify the docker-compose.yml has the volume mount:
         grep license.key /opt/mims/docker-compose.yml
       Should show: - ./license.key:/app/license.key:ro
    3. Restart:
         docker compose down && docker compose up -d

------------------------------------------------------------------------
PROBLEM: License validation failed — EXPIRED
------------------------------------------------------------------------

  CAUSE: The license expiry date has passed.

  SOLUTION:
    Contact the vendor to renew the license.
    Vendor will generate a new license.key with an extended expiry date.

------------------------------------------------------------------------
PROBLEM: Backend container keeps restarting
------------------------------------------------------------------------

  Check logs:
    docker compose logs backend --tail=50

  Common causes:
    A. License failure (see above)
    B. Database not ready — wait 30 seconds and check again
    C. Wrong database password in .env — verify DB_PASSWORD is correct

------------------------------------------------------------------------
PROBLEM: Cannot connect from browser — "This site can't be reached"
------------------------------------------------------------------------

  Steps:
    1. Check that all containers are running:
         docker compose ps
    2. Check nginx is up:
         docker compose logs nginx
    3. Check firewall:
         sudo ufw status
         sudo ufw allow 80/tcp
    4. Check server IP address:
         ip addr show
    5. Try from the server itself first:
         curl http://localhost/

------------------------------------------------------------------------
PROBLEM: Server rebooted — system did not start automatically
------------------------------------------------------------------------

  Check the systemd service:
    sudo systemctl status mims.service

  If inactive, start it:
    sudo systemctl start mims.service

  If failed, re-enable:
    sudo systemctl daemon-reload
    sudo systemctl enable mims.service
    sudo systemctl start mims.service

------------------------------------------------------------------------
PROBLEM: Database password mismatch error
------------------------------------------------------------------------

  If you changed the DB_PASSWORD in .env after the database was already
  created, the database still has the old password.

  Solution — reset the database password:
    docker compose exec postgres psql -U postgres -c \
      "ALTER USER mims_user WITH PASSWORD 'YOUR_NEW_PASSWORD';"

------------------------------------------------------------------------
PROBLEM: Disk space running low
------------------------------------------------------------------------

  Check disk usage:
    df -h /opt/mims/

  Clean up old Docker resources:
    docker system prune -f --volumes    # WARNING: removes stopped containers

  Clean up old backups manually:
    ls -lh /opt/mims/backups/
    rm /opt/mims/backups/mims_backup_OLD_DATE.sql.gz

PART K  —  SECURITY CHECKLIST BEFORE HANDOFF
================================================================================

  Complete this checklist before handing the system to the client.

  [ ] license.key is in place and system starts successfully
  [ ] Default admin password has been CHANGED
  [ ] All passwords in .env are strong (not default values)
  [ ] .env file permissions are 600  (chmod 600 /opt/mims/.env)
  [ ] license.key file permissions are 444 (read-only)
  [ ] Firewall is configured — only port 80 is open to the LAN
  [ ] Ports 3000, 3001, 5432, 6379 are NOT open to the outside
  [ ] Database backup cron job is configured and tested
  [ ] System auto-starts on reboot (systemd service enabled)
  [ ] Client IT staff has been trained to check logs
  [ ] Vendor records (license.info, machine fingerprint form) are saved
  [ ] Client has been told NOT to share .env or license.key files

  DO NOT HAND OVER:
  [ ] Source code (src/ folders) — ❌ Never
  [ ] TypeScript files (*.ts)    — ❌ Never
  [ ] Development machine .env   — ❌ Never
  [ ] license.info vendor record — ❌ Never
  [ ] Git repository access      — ❌ Never
